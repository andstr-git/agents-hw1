### Доменный слой

В `domain.mjs` находятся чистые функции без DOM и глобального `localStorage`:

- исходный пример: «Чтение» — 2 ч, `done=true`; «Практика» — 4 ч, `done=false`; «Повторение» — 2 ч, `done=false`;
- валидация названия после `trim`: пустая строка и одни пробелы отклоняются;
- валидация часов: число от 0,5 до 24 с шагом 0,5; пустое поле не считается нулём; отрицательные, нечисловые значения и значения вне границ отклоняются;
- десятичная запятая нормализуется в точку, поэтому `3,5` принимается наравне с `3.5`;
- добавление, удаление и переключение `done` не мутируют исходный массив;
- фильтрация `all` / `active` / `done` применяется только к видимому списку;
- итоги считаются по всем задачам: сумма часов, сумма часов выполненных и `Math.round(100 × done / total)`;
- пустой список даёт 0 ч и 0 % без `NaN`/`Infinity`;
- сохранённые задачи проверяются перед загрузкой: повреждённые данные отбрасываются.

### Приложение и хранение

- `buildViewModel(tasks, filter)` собирает видимый список, итоги, прогресс, подписи фильтров и сообщение пустого состояния.
- Импорт `app.mjs` в Node безопасен: DOM запускается только при `typeof document !== "undefined"`.
- Задачи сохраняются в `localStorage` под ключом `task-tracker.tasks.v1`; фильтр не сохраняется.
- При недоступном или переполненном хранилище показывается сообщение, приложение продолжает работать в памяти.
- При повреждённом JSON загружается исходный пример и выводится уведомление о сбросе.
- Форма при ошибке не очищается: значения остаются для исправления, ошибка показывается рядом с соответствующим полем.
- Пустое состояние показывает понятное сообщение, сводку 0 ч / 0 %, форма и фильтры остаются активными.

### Интерфейс

- Сводка: всего часов, выполнено часов, прогресс и полоса прогресса.
- Список задач: чекбокс статуса, название, часы и кнопка «Удалить» с доступной подписью.
- Фильтры «Все», «Активные», «Готовые» с `aria-pressed`; на прогресс и итоги не влияют.
- Подписи полей через `<label>`, подсказка по часам, `role="alert"` у ошибок.
- Ширина 390 px: элементы не выходят за область просмотра, длинные названия переносятся.

## Соответствие ожиданиям

- Исходный пример: 3 задачи, всего 8 ч, выполнено 2 ч, прогресс 25 % по часам, а не 33 % по числу задач.
- После отметки «Практики»: 6 из 8 ч, прогресс 75 %.
- Фильтр «активные»: видны только «Практика» и «Повторение», общий прогресс остаётся 25 %.
- После удаления всех задач: 0 ч и 0 %, без `NaN`/`Infinity`.

## Исправленный баг: часы через запятую

### Симптом

Пользователь вводил часы в привычном виде `3,5`, как подсказано в форме («Например, 1,5»), но задача не добавлялась: появлялась ошибка «Часы должны быть числом». Значение `3.5` с точкой при этом работало.

### Причина

В `validateHours` строка приводилась к числу напрямую:

```js
value = Number(trimmed);
```

`Number("3,5")` возвращает `NaN`, поэтому корректное по смыслу значение отбрасывалось на шаге «часы должны быть числом». Подсказка интерфейса и фактическое поведение противоречили друг другу.

### Исправление

Перед разбором запятая нормализуется в точку:

```js
value = Number(trimmed.replace(",", "."));
```

Дополнительно:

- в `tests/acceptance.test.mjs` добавлены проверки `0,5`, `3,5`, ` 3,5 `, `24,0`, а также отказов для `3,7` (нарушен шаг 0,5) и `3,5,5` (нечисловое значение);
- в `specs/tracker/spec.md` добавлен сценарий «Часы с запятой»;
- в `design.md` зафиксирована нормализация разделителя;
- в `tasks.md` добавлена и закрыта задача 6.1.

### Проверка исправления

Выполнено в браузере через локальный HTTP-сервер:

- ввод `3,5` → ошибки нет, задача добавлена, в списке «3,5 ч», итог 11,5 ч, прогресс 17 %; в `localStorage` сохранено число `3.5`;
- ввод `3,7` → ошибка «Часы должны быть кратны 0,5», задача не добавлена, введённое значение осталось в поле;
- после очистки `localStorage` и перезагрузки снова видны 3 задачи, 8 ч, 25 %.

Автотесты после исправления: **38/38**.

## Запуск

- Приложение нужно открывать через локальный HTTP-сервер: браузеры блокируют ES-модули по `file://`. Сервер должен отдавать `.mjs` как `text/javascript`.
- Для этого подойдёт Live Server в VS Code или локальный сервер с корректной MIME-картой. По наблюдению из отчёта варианта `direct`, обычный `python -m http.server` на этой Windows-машине отдаёт `.mjs` как `text/plain`; для него нужна настройка MIME.
- Автотесты запускаются без сервера и без установки зависимостей:

```powershell
node --test tests/acceptance.test.mjs
```

- `localStorage` привязан к origin: смена порта или `localhost` / `127.0.0.1` создаёт другое хранилище.

## Ограничения и заметки

- Внешних зависимостей, CDN и сетевых запросов нет; `package.json` намеренно не добавлялся.
- Фильтр не сохраняется между перезагрузками — сохраняются только задачи.
- Повреждённые сохранённые данные заменяются исходным примером с уведомлением.
- Автотесты не эмулируют DOM: вёрстка, события формы и поведение браузерного хранилища проверялись вручную.
- Не выполнялись: проверка на реальном мобильном устройстве, в других браузерах, аудит доступности и Lighthouse.
