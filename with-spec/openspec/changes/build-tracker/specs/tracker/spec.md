# Spec Delta

## Purpose

Мини-трекер учебных задач на неделю: ведёт список задач с часами и статусом, валидирует ввод, фильтрует видимый список и показывает суммарные часы и прогресс по часам без внешних зависимостей.

## ADDED Requirements

### Requirement: Исходный пример данных
При первом запуске без сохранённого состояния приложение SHALL показывать три задачи: «Чтение» — 2 ч, done=true; «Практика» — 4 ч, done=false; «Повторение» — 2 ч, done=false.

#### Scenario: Первый запуск
- **WHEN** приложение открыто впервые и сохранённых данных нет
- **THEN** в списке ровно 3 задачи с указанными названиями, часами и статусами

#### Scenario: Итоги исходного примера
- **WHEN** показан исходный пример
- **THEN** всего 8 ч, выполнено 2 ч, прогресс 25 % по часам, а не 1/3 по числу задач

### Requirement: Добавление задачи
Приложение SHALL добавлять задачу с валидными названием и часами, назначать ей уникальный идентификатор и статус done=false, после чего список, итоговые часы и прогресс MUST обновиться.

#### Scenario: Успешное добавление
- **WHEN** введены название «Конспект» и часы 1,5 и форма отправлена
- **THEN** задача появляется в списке со статусом «активная», итоговые часы увеличиваются на 1,5, прогресс пересчитывается

#### Scenario: Название очищается от пробелов
- **WHEN** введено название с пробелами по краям, например «  Конспект  »
- **THEN** задача сохраняется с названием «Конспект» без крайних пробелов

### Requirement: Валидация названия
Название задачи после trim MUST быть непустым. При невалидном названии задача не добавляется, рядом с полем названия видна ошибка, а введённые значения формы сохраняются.

#### Scenario: Пустое название
- **WHEN** поле названия пустое и форма отправлена
- **THEN** задача не добавляется, рядом с полем названия видна ошибка, остальные введённые значения остаются в форме

#### Scenario: Название из пробелов
- **WHEN** в поле названия введены только пробелы и форма отправлена
- **THEN** задача не добавляется и рядом с полем названия видна ошибка

### Requirement: Валидация часов
Часы MUST быть числом от 0,5 до 24 включительно с шагом 0,5. Пустое значение не равно нулю. При невалидных часах задача не добавляется, рядом с полем часов видна ошибка, введённые значения формы сохраняются.

#### Scenario: Пустые часы
- **WHEN** поле часов пустое и форма отправлена
- **THEN** задача не добавляется и рядом с полем часов видна ошибка

#### Scenario: Отрицательные часы
- **WHEN** введены часы -1 и форма отправлена
- **THEN** задача не добавляется и рядом с полем часов видна ошибка

#### Scenario: Ниже минимума
- **WHEN** введены часы 0,4 и форма отправлена
- **THEN** задача не добавляется и рядом с полем часов видна ошибка

#### Scenario: Выше максимума
- **WHEN** введены часы 24,5 и форма отправлена
- **THEN** задача не добавляется и рядом с полем часов видна ошибка

#### Scenario: Допустимые границы
- **WHEN** по отдельности отправлены значения 0,5 и 24
- **THEN** в обоих случаях задача добавляется без ошибки

#### Scenario: Нарушен шаг 0,5
- **WHEN** введены часы 1,3 и форма отправлена
- **THEN** задача не добавляется и рядом с полем часов видна ошибка

#### Scenario: Допустимый шаг 0,5
- **WHEN** введены часы 1,5 и форма отправлена
- **THEN** задача добавляется без ошибки

#### Scenario: Часы с запятой
- **WHEN** введены часы 3,5 через запятую и форма отправлена
- **THEN** задача добавляется с часами 3,5 без ошибки

### Requirement: Ошибки не меняют данные
Неуспешная отправка формы MUST NOT изменять список задач, итоговые часы и прогресс. Ошибка MUST исчезать после успешной отправки.

#### Scenario: Невалидная отправка при существующих задачах
- **WHEN** форма отправлена с невалидными данными при трёх исходных задачах
- **THEN** список по-прежнему содержит те же 3 задачи, итоги остаются 8 ч и 25 %

#### Scenario: Исправление после ошибки
- **WHEN** после ошибки пользователь исправляет данные и успешно отправляет форму
- **THEN** ошибка больше не отображается, а задача добавлена

### Requirement: Удаление задачи
Приложение SHALL удалять выбранную задачу из данных и из списка. После удаления итоговые часы, выполненные часы и прогресс MUST пересчитываться.

#### Scenario: Удаление одной задачи
- **WHEN** удалена задача «Повторение» из исходного примера
- **THEN** в списке остаются 2 задачи, всего 6 ч, выполнено 2 ч, прогресс 33 %

### Requirement: Переключение статуса
Приложение SHALL переключать done выбранной задачи, изменяя и данные, и интерфейс. После переключения итоговые часы, выполненные часы и прогресс MUST пересчитываться.

#### Scenario: Отметка «Практики» готовой
- **WHEN** задача «Практика» отмечена выполненной
- **THEN** выполнено 6 из 8 ч и прогресс равен 75 %

#### Scenario: Снятие отметки
- **WHEN** у выполненной задачи «Практика» статус снят
- **THEN** выполнено снова 2 из 8 ч и прогресс равен 25 %

### Requirement: Прогресс по часам
Прогресс MUST вычисляться как округление 100 × (сумма часов выполненных задач / сумма часов всех задач). При отсутствии задач прогресс MUST быть 0 % без NaN и Infinity.

#### Scenario: Прогресс по часам, а не по количеству
- **WHEN** из трёх задач выполнена одна задача на 2 ч из 8 ч
- **THEN** прогресс равен 25 %, а не 33 %

#### Scenario: Округление прогресса
- **WHEN** выполнено 2 ч из 6 ч
- **THEN** прогресс равен 33 %

#### Scenario: Нет задач
- **WHEN** задач нет
- **THEN** прогресс равен 0 % и не содержит NaN или Infinity

### Requirement: Фильтрация списка
Приложение SHALL поддерживать фильтры «все», «активные» и «готовые». Фильтр MUST влиять только на видимый список; итоговые часы, выполненные часы и прогресс MUST считаться по всем задачам.

#### Scenario: Фильтр «активные»
- **WHEN** выбран фильтр «активные» при исходном примере
- **THEN** в списке только «Практика» и «Повторение», а прогресс остаётся 25 %

#### Scenario: Фильтр «готовые»
- **WHEN** выбран фильтр «готовые» при исходном примере
- **THEN** в списке только «Чтение», а итоговые часы остаются 8 ч и прогресс 25 %

#### Scenario: Возврат ко всем задачам
- **WHEN** после фильтра выбран «все»
- **THEN** в списке снова все задачи, итоги не изменились

### Requirement: Итоговые часы
Приложение SHALL показывать общие часы всех задач и часы выполненных задач. Оба значения MUST учитывать все задачи независимо от фильтра и MUST обновляться после добавления, удаления и переключения статуса.

#### Scenario: Итоги при фильтре
- **WHEN** включён фильтр «активные»
- **THEN** по-прежнему показано 8 ч всего и 2 ч выполнено

#### Scenario: Итоги после удаления всех задач
- **WHEN** удалены все задачи
- **THEN** показано 0 ч всего и 0 ч выполнено

### Requirement: Пустое состояние
Когда задач нет, приложение MUST показывать 0 ч, 0 ч выполнено и 0 % прогресса без NaN и Infinity, а интерфейс MUST оставаться работоспособным: форму можно отправить, фильтры доступны.

#### Scenario: Удаление всех задач
- **WHEN** пользователь удалил все задачи
- **THEN** показано 0 ч и 0 %, в значениях нет NaN или Infinity

#### Scenario: Добавление после пустого состояния
- **WHEN** после удаления всех задач добавлена валидная задача на 2 ч
- **THEN** задача появляется, всего 2 ч, прогресс 0 %

#### Scenario: Фильтр при пустом списке
- **WHEN** задач нет и выбран фильтр «активные»
- **THEN** список пуст, итоги остаются 0 ч и 0 %, ошибок нет

### Requirement: Читаемость на узком экране
Интерфейс MUST оставаться читаемым при ширине окна 390 px: без горизонтального скролла, с подписанными полями ввода и кнопками.

#### Scenario: Ширина 390 px
- **WHEN** приложение открыто при ширине области просмотра 390 px
- **THEN** страница не имеет горизонтальной прокрутки, все поля и кнопки имеют видимые подписи

### Requirement: Автономная работа
Приложение MUST работать из локальных файлов без CDN, внешних библиотек, сетевых запросов и API-ключей.

#### Scenario: Открытие без сети
- **WHEN** приложение открыто локально при недоступной сети
- **THEN** все функции добавления, удаления, переключения статуса, фильтрации и подсчёта работают

### Requirement: Сохранение состояния
При доступном `localStorage` приложение SHALL сохранять задачи и восстанавливать их при следующем открытии. При недоступном или переполненном хранилище приложение MUST показывать понятное сообщение и продолжать работу в памяти.

#### Scenario: Восстановление после перезагрузки
- **WHEN** пользователь добавил задачу и перезагрузил страницу при доступном хранилище
- **THEN** добавленная задача и её статус сохранены

#### Scenario: Хранилище недоступно
- **WHEN** доступ к `localStorage` выбрасывает ошибку
- **THEN** показано понятное сообщение, приложение продолжает работать с задачами в памяти
